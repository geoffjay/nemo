* **Feature**: Implemented [SFC Phase 3 — scoped `<style>` folding](/docs/knowledgebase/plans/sfc-components.md). An SFC's `<style>` block is now folded at compile time onto matching template nodes as inline attributes (there is no runtime cascade in nemo — styling is inline attrs consumed by `apply_layout_styles`). All in **nemo runtime**: `fold_sfc_styles` runs in the `parse_layout_config` SFC loop *before* `rewrite_sfc_tags`/`rewrite_sfc_handlers` so type/id selectors match the raw markup. `parse_style_rules` parses a CSS subset — **v1 selectors: type (`button {}`) and `#id`**, plus comma-separated selector lists and `/* */` comments; no class/combinator/pseudo/media. `normalize_style_prop` maps CSS names to nemo universal-style attrs (special-cases `border-radius`→`rounded`, `background-color`→`background`; else kebab→snake) and drops names not in `nemo_registry::universal_style_attributes()`; `coerce_style_value` coerces per the attr's `value_type` (strips `px` for integers, parses float/bool, else string). `apply_style_rules` walks the template folding each matching rule's decls **only where the attr is absent** (id rules before type rules), giving precedence `<style>` → template inline attr → instance attr; colors stay strings resolved (incl. `theme.*`/roles) at render by `apply_layout_styles`, so no fold-time `resolve_color`. Unknown props/selectors/values warn and drop. Scoping is inherent (folding only touches the SFC's own subtree). * **Plan**: Added [SFC Phase 6 — raw-text `.nemo` parser (drop the CDATA requirement)](/docs/knowledgebase/plans/sfc-components.md) after establishing that `nemo build` does **not** remove the CDATA dependency: `.nemo` is parsed with `quick-xml` (a general XML reader with no raw-text elements), so `<style>`/`<script>` bodies containing `<`/`&` need `<![CDATA[…]]>`, and `nemo build` reuses `XmlParser::parse_sfc` verbatim — the CDATA rule is upstream of the entire build pipeline. Dropping it is a **parser-layer** change independent of every other phase. Approach: a top-level block pre-splitter in `parse_sfc` that runs *before* `quick-xml`, treats `<script>`/`<style>` as HTML-style **raw-text** elements (captured verbatim to the literal close tag — also dissolving the current "first contiguous text/CDATA run only" limit), and feeds **only** `<template>` to the XML reader (template markup stays XML, `${prop}` unchanged). Backward-compatible (strip optional leading `<![CDATA[`/trailing `]]>` so existing examples still load); `.nemo`-only (does not touch `process_root`/`app.xml`); `SfcDefinition` shape unchanged so runtime/build/render are all untouched. Edge cases flagged: `</script>` inside a Rhai string literal (same known HTML limitation), CRLF, empty/missing block, template text resembling `<script>`. * **Feature**: Implemented [single-file components (`.nemo` SFCs)](/docs/knowledgebase/plans/sfc-components.md) — Phase 0 (import, tag rewrite, default slot, `${prop}` interpolation) + Phase 1 (scoped `<script>`). An SFC is a namespaced, file-scoped superset of `<template>`: one `.nemo` file with `<template>`/`<style>`/`<script>` compiles to a `TemplateMap` entry + a `sfc:<tag>` script + a tag-rewrite, so an expanded SFC is ordinary built-ins by render time (no `app.rs`/`render_component` changes). **nemo-config**: `XmlParser::parse_sfc` → `SfcDefinition { name, template, style, script }` (flattens the single `<template>` root via the existing `process_component_element`); new `<imports>`/`<import src as>` arms in `process_root` resolve `src` relative to `base_dir`, parse the SFC, and store it under a top-level `sfc[tag]` map (tag = `as=` > `<template name>` > filename stem, **kebab→snake normalized** to match how `<labeled-button>` parses to type `labeled_button`). The **resolver skips the `sfc` subtree** so bare `${prop}` survives to runtime interpolation (distinct from load-time `${var.x}`). **nemo-extension**: added `ExtensionManager::load_script_source(id, source)` for inline (file-less) scripts. **nemo runtime**: in `parse_layout_config`, merge each SFC template into the `TemplateMap` (rewriting template-authored bare `on_*` → `sfc:<tag>::<fn>` via `rewrite_sfc_handlers`, and nested SFC tags for composition), then `rewrite_sfc_tags` converts every `<tag>` usage into a `template="tag"` instance (dropping `type`, folding scalar attrs into `vars` for `${}` **and** keeping them for deep-merge overlay, preserving `component` children for slot injection) **before** `expand_children` — so deep-merge, slot injection, and `__anon`/id-scoping all apply unchanged. SFC scripts load under `sfc:<tag>` (single colon, then `::fn`) so `call_handler`'s first-`::` split needs no change; one script serves all instances, distinguished by the scoped `component_id`. **validate**: `nemo validate --strict` now treats registered SFC tags as known component types (skips `unknown-component`), like a `template=`-driven node.
